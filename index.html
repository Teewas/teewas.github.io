    Hi, I’m Toluwase. I press the buttons you hoped nobody would.

    I started out building websites, so I know how much care goes into every button. Then I switched sides. Now my job is to find out what happens when someone uses that button in a way nobody planned.

    Typing two digits into a phone field. Double-clicking Pay. Squeezing a page onto a tiny screen. It sounds like mischief, and it is, with a purpose: the bug I find today is a customer who doesn’t get stuck tomorrow.

    I’m ISTQB certified, I test live sites for well-known fashion and telecoms brands, and I write bug reports so clear that nobody has to ask “can you show me that again?”

    How I test

    1. 01

      Read the requirement

      I work out what the feature should do and where the unclear parts are.

    2. 02

      Break the happy path

      Empty fields, odd input, double clicks, slow connections and small screens.

    3. 03

      Write it up clearly

      Steps, expected against actual, screenshots and console logs, so it gets fixed.

    4. 04

      Check the fix

      I retest the fix and run a regression pass around it.
